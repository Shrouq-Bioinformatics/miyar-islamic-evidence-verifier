01 / المشكلة والفرصة

المشكلة ليست غياب الإجابة فقط؛
بل غياب أثر الدليل.

تصل ادعاءات إلى فرق المحتوى بإحالات ناقصة، أو خلط بين النص والتفسير والرأي والفتوى. البحث اليدوي بطيء، بينما قد تمنح الأدوات العامة إجابة لا تكشف حدودها.

01

إحالة ناقصة

اسم كتاب أو آية بلا نص مسترجع أو سياق أو نسخة.

02

خطر الثقة الزائفة

صياغة واثقة قد تتحول سريعًا إلى مادة منشورة.

03

قرار غير قابل للتتبع

لا يظهر لماذا توقف المحرر أو أحال المسألة إلى مختص.

سؤال التصميم

كيف نسرّع الوصول إلى إحالة قابلة للتتبع، مع رفع جودة التوقف الآمن حين لا يكفي الدليل؟

المستخدمون

أساسيمحرر المحتوى الدعوي/التربوي

يحتاج قرارًا واضحًا قبل النشر.

حاسمالمراجع المختص

يحتاج الادعاء والسياق وسبب الإحالة في مكان واحد.

02 / الحل والمنهجية

القرار البشري هو نهاية المسار،
لا هامشًا حول النموذج.

مِعيار واجهة عربية RTL تستقبل المطالبة كما وردت، وتفصل طبقات العمل كي لا يصبح ذكر المرجع مرادفًا لإثباته.

1 — الإدخالالادعاء والسياق واللغة كما وصلت للفريق.
2 — الاسترجاعنص موثق ومقطع وسياق. غير منفذ حاليًا.
3 — الفرزدعم أولي / مراجعة / أدلة غير كافية.
4 — القرارمراجع بشري يعتمد أو يرفض قبل النشر.

ما يعمل اليوم

  • لوحة وسجل حالات وغرفة مراجعة.
  • API للتحقق من المدخلات ومخرجات مقيدة.
  • قواعد محلية معلنة تتوقف أو تحيل.
  • مكتبة روابط وإعدادات أمان.
  • حفظ في متصفح الجهاز.

كيف يعمل الوضع المحلي؟

  1. يرصد أسماء مصادر أو ألفاظ مسائل معاصرة.
  2. لا يجلب أي نص ولا يثبت النسبة.
  3. لا يعيد حالة «مدعوم» ولا ثقة مقاسة.
  4. ينتج إحالة بشرية أو «أدلة غير كافية».
حتى مسار المزود التجريبي ليس تحققًا. فهو يحلل الادعاء مع فهرس وصفي فقط، بلا retrieval أو اقتباسات مسترجعة. تصفية معرفات المصادر تقلل شكلًا من الهلوسة، لكنها لا تثبت صحة الإحالة.

03 / الحدود والخصوصية

ما لا يفعله مِعيار الآن

حدود تقنية

  • المفتاح الحالي مرفوض، ولم يُستبدل.
  • لا استرجاع أو مطابقة لنصوص المصادر.
  • لا مجموعة اختبار أو أرقام دقة موثقة.
  • رابط العرض العام ومستودع GitHub العام متاحان.
  • الأرقام النموذجية في الواجهة ليست قياسات حقيقية.

حدود تشغيلية

  • لا تسجيل دخول أو أدوار أو صلاحيات فريق.
  • لا قاعدة بيانات لمسار المنتج أو سجل تدقيق مركزي.
  • لا مزامنة أو نسخ احتياطي للحالات.
  • لا سياسة احتفاظ أو حذف مركزي منفذة.
  • لا مراجعة شرعية/قانونية نهائية.

خريطة البيانات الحالية

البياناتالمكان/الجهةالملاحظة
الحالات والأنشطة والمصادر المحفوظةlocalStorageعلى المتصفح نفسه؛ تمسح مع بيانات الموقع.
المطالبة والسياق واللغةخادم API؛ وOpenAI عند مفتاح صالحلا توجد شاشة موافقة تفصيلية حاليًا.
سجلات تشغيل HTTPالخادممدة الاحتفاظ غير محددة.
قاعدة العرض: استخدم بيانات عامة أو مصطنعة فقط. لا تدخل أسماء أشخاص، محادثات خاصة، معلومات صحية، أو أسرار. أي مستخدم لملف المتصفح نفسه قد يرى السجل المحلي.

قبل الإنتاج

موافقة واضحة قبل الإرسال الخارجي، تنقيح PII، تشفير، إدارة أسرار، أدوار وعزل فرق، مدد احتفاظ وحذف، سجل تدقيق، اتفاقية معالجة مع المزود، وخطة حوادث — إضافة إلى توثيق تراخيص المصادر ونسخها.

05 / إعادة الإنتاج

بناء مطابق للـworkspace الحالي

المتطلبات: Node.js 24 وpnpm. لا تضع أي مفتاح في الكود أو الأرشيف.

pnpm install --frozen-lockfile
pnpm run typecheck
PORT=24752 BASE_PATH=/ \
  pnpm --filter @workspace/miyar-evidence-verifier run build
pnpm --filter @workspace/api-server run build

تشغيل الخدمات

# API
PORT=8080 pnpm --filter @workspace/api-server run dev

# Web
PORT=24752 BASE_PATH=/ \
  pnpm --filter @workspace/miyar-evidence-verifier run dev
تفصيل مهم: الواجهة تستدعي /api/verify نسبيًا. إعداد Replit artifact router يجمع الواجهة وAPI على أصل واحد. خارج Replit يلزم reverse proxy يوجه /api/* إلى المنفذ 8080؛ تشغيل منفذين منفصلين وحده لا يربط المسار.

حقائق النشر

  • إعداد Replit الحالي: autoscale، والـAPI يستخدم PORT=8080.
  • الواجهة تبنى إلى artifacts/miyar-evidence-verifier/dist/public.
  • لا يحتاج الوضع المحلي مفتاح AI أو DATABASE_URL.
  • وجود حزمة DB في workspace لا يعني أن المنتج الحالي يخزن فيها.
  • رابط العرض العام: https://maayr-islamic-evidence-verifier.replit.app؛ يلزم إعادة نشر آخر التغييرات ثم إعادة الاختبار.
