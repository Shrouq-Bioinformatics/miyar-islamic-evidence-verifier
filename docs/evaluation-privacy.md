# التقييم والخصوصية — بروتوكول تنفيذي

## فرضيات قابلة للاختبار

1. يقلل مِعيار وسيط زمن الوصول إلى إحالة قابلة للتتبع مقارنة بالبحث اليدوي.
2. يرفع اكتشاف الحالات التي يجب إيقافها وإحالتها.
3. لا يزيد الدعم الزائف أو الإحالات المختلقة.

## تصميم الدراسة

- **العينة:** 120–200 حالة موزونة حسب الفئة والخطورة، مع فصل 20% للضبط و80% للاختبار النهائي.
- **المرجع الذهبي:** مراجعان مستقلان وثالث للحسم؛ تسجيل المصدر/المقطع/السياق وحالة القرار.
- **المقارنة:** نفس المحررين ينفذون بحثًا يدويًا ومسار مِعيار بترتيب متوازن؛ يمنع تسرب الإجابات.
- **المقاييس:** دقة الإحالة، recall للإحالة البشرية، الدعم الزائف، الامتناع، الزمن، κ، وشدة الضرر المتوقعة.
- **بوابة مقترحة:** لا إحالات مختلقة، recall ≥95% للحساس، و100% مراجعة بشرية للفتاوى/المعاصر.
- **التقرير:** نشر حجم العينة، فواصل الثقة، الأخطاء حسب الفئة، وإصدار المصادر والنموذج. لا انتقاء لأفضل المحاولات.

لم يُنفذ هذا البروتوكول بعد؛ لا توجد أرقام أداء يمكن الاستشهاد بها.

## جرد البيانات الحالي

| البيانات | المكان/الجهة | الغرض | الاحتفاظ الحالي |
|---|---|---|---|
| نص المطالبة، السياق، اللغة | API؛ وقد تصل إلى OpenAI عند مفتاح صالح | الفرز الأولي | غير موثق مركزيًا في التطبيق |
| النتيجة وملاحظة المراجع والنشاط | `localStorage` | استمرار العرض في المتصفح | حتى يمسح المستخدم بيانات الموقع |
| سجلات HTTP تشغيلية | خادم API | التشغيل والتشخيص | سياسة المدة غير محددة |

## قواعد العرض الآمن

- بيانات مصطنعة أو عامة فقط؛ لا PII ولا أسرار ولا قضايا أفراد.
- لا حسابات مشتركة لأن المصادقة غير موجودة أصلًا.
- مسح بيانات الموقع بعد العرض على جهاز مشترك.
- عدم إدخال مفتاح في الواجهة أو المستودع أو ZIP.
- عند تفعيل مزود خارجي: إظهار الموافقة والغرض والجهة المستلمة قبل الإرسال.

## متطلبات ما قبل الإنتاج

- تصنيف البيانات وتنقيح PII قبل الإرسال.
- تشفير، إدارة أسرار، أدوار وصلاحيات، عزل فرق، وسجل تدقيق.
- مدد احتفاظ وحذف/تصدير، ونسخ احتياطي واختبار استعادة.
- تقييم أثر خصوصية واتفاقية معالجة مع المزود وتحديد الإقليم.
- سياسة تسجيل تمنع نص المطالبة والتوكنات، وخطة استجابة للحوادث.
- توثيق تراخيص المصادر ونسخها وتواريخ مراجعتها.
